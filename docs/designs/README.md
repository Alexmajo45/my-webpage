# Designs

Approved specifications live here, one file per design, numbered in order: `0002-library-enrichment.md` and so on.

A spec is drafted by the Master with the user, reviewed with `/spec-review`, and carries a status line at the top: `Draft`, `In review` or `Approved (date)`. Only approved specs are decomposed into task cards.

A spec states the problem, the approach, what was rejected, the data and interfaces affected, the security considerations, and how we will know it worked. It must be understandable by someone who was not in the conversation, because that is exactly who reviews it.

The M0 foundation was built before this gate existed. Its design is recorded after the fact in `docs/02-architecture.md` and has not been through spec review.
